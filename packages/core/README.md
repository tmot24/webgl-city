# @webgl-city/core

Ядро WebGL2 City: генерация города, WebGL2-рендер, камера, лучи, алгоритмы и подготовка данных для UI.
Не зависит ни от одного UI-фреймворка — его используют оба приложения, [Angular](../../apps/angular) и [React](../../apps/react).
Единственная зависимость — `gl-matrix`.

Приложения — тонкие адаптеры: связывают ядро со своей реактивностью (сигналы или MobX) и своим жизненным циклом. Вся логика сцены живёт здесь в одном экземпляре.

---

## Принципы

- **Без фреймворка.** Ни одного импорта из Angular или React. Функции принимают DOM-элементы и данные, а не `ElementRef`, сигналы или хуки.
- **Ресурс возвращает свою очистку.** Всё, что создаёт GL-ресурсы или подписки, возвращает `dispose` / функцию остановки. Когда её вызвать, решает владелец: `destroyRef.onDestroy(stop)` в Angular, `return stop` из `useEffect` в React.
  ```ts
  const stop = observeCanvasSize({ canvas, onResize });   // подписка
  const unbind = bindOrbitControls({ canvas, onRotate, onPan, onZoom }); // ввод
  const renderer = createCityRenderer({ canvas, instanceData, ground, road }); // GL-ресурсы
  renderer.dispose();
  ```
- **Кадр как данные.** Рендер не хранит состояние сцены: `render(frame)` рисует переданный `CityFrame` (размер, камера, свет, выделение, линия). Когда и как часто рисовать, решает адаптер.
- **Неизменяемое состояние, чистые переходы.** Камера — значение `OrbitState`, действия — функции `(состояние, дельта) → новое состояние` (`rotateOrbit`, `panOrbit`, `zoomOrbit`). Хранить его можно в чём угодно: в сигнале, в MobX.
- **Ввод отдельно от состояния.** `bindOrbitControls` и `bindCanvasPointer` переводят события мыши в намерения (дельты, лучи) и ничего не меняют сами.
- **Параметры — один объект с именованными полями.** Во всём API: `createOrbitState({ eye, center })`, `findPath({ graph, start, finish })`.

## Рендеринг

- **Инстансинг.** Весь город (тысячи зданий) рисуется одним `drawElementsInstanced`. На инстанс передаются только позиция и габариты (`vertexAttribDivisor`), трансформация применяется в вершинном шейдере.
- **Тени (shadow mapping).** Depth-проход из позиции солнца в карту 4096×4096, мягкие края через PCF 3×3, защита от «теневого акне»: bias, зависящий от угла света, плюс отсечение передних граней в проходе глубины.
- **Тени следуют за камерой.** Статичная карта на весь город упирается в компромисс «охват против разрешения», поэтому ортобокс света центрируется на фокусе камеры и масштабируется зумом: резкость там, куда смотришь.
- **Освещение.** Направленный свет по модели Half-Lambert: мягкий терминатор и читаемые затенённые грани.
- **Линия поверх сцены.** Отрезок измерения и маршрут рисуются лентой постоянной экранной толщины.
- **Двухпроходная отрисовка** в `createCityRenderer`: карта теней, затем сцена с картой теней на текстурном юните.

```ts
const renderer = createCityRenderer({ canvas, instanceData, ground, road });

renderer.render({
  size: { width, height },
  camera: { viewProjection, eye, center, distance },
  light: { directionNorm, castShadows: true },
  selectedId: -1,
  polyline: null,
});

renderer.dispose();
```

Перерисовка только по изменению данных, без постоянного цикла: адаптеры вызывают `render`, когда меняется что-то из кадра, и не чаще раза за кадр браузера.

## Взаимодействие и алгоритмы

- **Орбитальная камера** на сферических координатах: свободный азимут, ограниченный наклон, мультипликативный зум, пан с одинаковым «сцеплением» на любом зуме.
- **Пикинг.** Луч из камеры через точку клика, пересечение с AABB зданий (ray–box) и с прямоугольником земли.
- **Прилипание в экранных пикселях.** Кандидаты (8 углов здания или перекрёсток с углами) проецируются на экран, близость меряется в пикселях, а не в метрах. Прилипание одинаково лёгкое на любом расстоянии и зуме.
- **Граф дорог** — узлы-перекрёстки и взвешенные рёбра, построенные из сетки дорог.
- **A*** с евклидовой эвристикой. Она согласованная, поэтому маршрут гарантированно кратчайший. Приоритетная очередь — бинарная min-куча с ленивым удалением устаревших записей.
- **Детерминированная генерация.** Кварталы, дороги и высоты зданий строятся генератором псевдослучайных чисел (mulberry32) из фиксированного `seed`: один и тот же город при каждом запуске.

## Мост к UI

Ядро готовит для интерфейса всё, что не зависит от фреймворка. Компонентам остаётся только отрисовать.

- **Данные для панелей:** `toBuildingInfo`, `toMeasureRow`, `toRouteInfo` — форматированные значения для панели здания, лога измерений и сводки маршрута.
- **Проекция мир → экран:** `createScreenProjector` фиксирует камеру и размер canvas в одну функцию.
- **Метки поверх сцены:** `toMeasureLabel` считает подпись над серединой отрезка, `applyScreenOverlay` пишет видимость, позицию и текст прямо в элемент, `isSameOverlayData` сравнивает данные метки по содержимому. Позиция передаётся в CSS через `--anchor-x` / `--anchor-y`, сдвиг делает `transform`, без пересчёта раскладки.
- **Режимы и линия:** `SCENE_MODES`, `MODE_HINTS`, `selectActivePolyline`.

## Подключение

Пакет внутренний (npm workspaces) и отдаётся исходниками TypeScript, без отдельной сборки. Каждое приложение компилирует его своим сборщиком:

```ts
import { createCityRenderer } from '@webgl-city/core/render/create-city-renderer';
import { observeCanvasSize } from '@webgl-city/core/dom/observe-canvas-size';
```

Шейдеры (`.vert`, `.frag`, `.glsl`) импортируются как строки. Загрузку настраивает приложение:
- **Angular:** `"loader": { ".vert": "text", ".frag": "text", ".glsl": "text" }` в `angular.json`;
- **React (Vite):** небольшой плагин в `vite.config.ts`, превращающий файл шейдера в `export default "…"`.

Как ядро связано с реактивностью каждого фреймворка — в README приложений: [Angular](../../apps/angular), [React](../../apps/react).
